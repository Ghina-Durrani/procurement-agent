## 2. Rules enforced by tooling (IN REPO) — do not work around them

| Rule | Why |
|---|---|
| No `any`; no `@ts-ignore` (`@ts-expect-error` only with a description) | Type safety |
| No `dangerouslySetInnerHTML` | Request and LLM text is untrusted |
| No direct `fetch`; use `apiRequest` from `@/lib/api-client` | One place for base URL, headers, error shape |
| No deep imports into a feature (`@/features/x/y`); import only `@/features/x` | Features expose a public `index.ts` |
| `console.log` warns (only `warn`/`error` allowed) | No debugging leftovers |
| jsx-a11y recommended rules | Accessibility |
| Prettier: no semicolons, single quotes, trailing commas, width 100 | One formatting style (auto-fixed on commit) |
| `src/components/ui` and `src/types/api.generated.ts` are excluded from lint/format | Reserved for vendored/generated code |

Never disable these rules to make code pass; change the code. Changing a rule needs a `DECISIONS.md` entry.

## 3. Folder structure

```text
frontend/src/
├── main.tsx
├── App.tsx                    # providers + routes only (PROPOSED)
├── index.css                  # tailwind import + tokens (IN REPO)
├── styles/tokens.css          # design tokens (IN REPO)
├── lib/                       # api-client.ts, utils.ts (IN REPO)
├── test/setup.ts              # (IN REPO)
├── types/api.generated.ts     # GENERATED by `npm run gen:api`; never edit by hand
├── components/
│   ├── ui/                    # generic primitives (button, input, dialog…), vendored style; no domain logic
│   └── domain/                # app-specific shared components (IN REPO: PolicyOutcomeBadge)
└── features/                  # PROPOSED
    └── <feature>/             # e.g. requests, review-queue, audit, policies
        ├── index.ts           # the ONLY public entry point of the feature
        ├── api.ts             # functions that call apiRequest(); one per endpoint
        ├── hooks.ts           # React Query hooks wrapping api.ts
        ├── schemas.ts         # zod schemas for forms
        ├── components/        # feature-private components
        └── <Page>.tsx         # route-level page component
```

A feature may import from `@/components`, `@/lib`, and other features' `index.ts`; shared components never import from features.

## 4. Patterns

**Components**
- Function components, named exports (`export function X`), one component per file, file name = component name (`PascalCase.tsx`). Page-level default export only for `App.tsx`.
- Props declared as a `type XProps = {...}` next to the component. No `React.FC`.
- Merge classes with `cn()`; accept an optional `className` on reusable components.
- Variants: use `class-variance-authority` once a component has more than a simple map. A small `as const` lookup (see `PolicyOutcomeBadge`) is fine for simple cases.
- Icons from `lucide-react`; decorative icons get `aria-hidden`. **Meaning is never conveyed by colour alone**: always text (or accessible label) plus colour.
- Policy outcomes are always rendered with `PolicyOutcomeBadge`. Do not restyle them ad hoc.

**Styling**
- Tailwind utility classes only. **No raw hex colours** in components. Add a token to `styles/tokens.css` (`@theme`) and use it as a class (e.g. `bg-outcome-block-bg`).
- Layout is responsive by default; no fixed pixel widths for page layout.

**Types and API**
- Types for API data come from `src/types/api.generated.ts`. Regenerate with `npm run gen:api` after backend schema changes, and commit the regenerated file (backend must be running).
- Shared literal types (e.g. `PolicyOutcome`) must match backend enum strings exactly.
- Wire format is `snake_case` (Handbook §3); do not rename fields in `api.ts`. Map to display values only at the UI edge.

**Server state (PROPOSED)** — TanStack Query: one `QueryClientProvider` in `main.tsx`/`App.tsx`; each endpoint wrapped by a hook in the feature's `hooks.ts`; query keys start with the feature name (`['requests', id]`). No manual `useEffect` fetching.

**Forms (PROPOSED)** — React Hook Form + `zodResolver`. The zod schema lives in the feature's `schemas.ts` and mirrors backend limits (e.g. max message length). Server `field_errors` are mapped onto fields. The server remains the authority.

**Routing (PROPOSED)** — `react-router`; route table in one place; one page component per route; protected routes check auth state, but real authorization is server-side.

**Errors** — `apiRequest` throws `ApiError` (`code`, `message`, `fieldErrors?`) (IN REPO). Screens show `message` to the user; they never show raw server text that could contain internals. Note the open mismatch with the backend envelope (Handbook §3, Q-002).

**Loading/empty/error states** — every data-driven view renders all three explicitly.

## 5. Testing

- Vitest + React Testing Library + `@testing-library/user-event`; co-located `Component.test.tsx`; query by role/text, not by class names.
- Use `it.each` for variant tables (see `PolicyOutcomeBadge.test.tsx`).
- Mock network with MSW handlers (PROPOSED location: `src/test/handlers.ts`), never by stubbing `fetch` in components.
- Test user-visible behaviour: loading, success, validation errors, server error, and permission-dependent UI.

## 6. Environment and commands

- `frontend/.env.example`: `VITE_API_BASE_URL=http://127.0.0.1:8000`. Copy to `frontend/.env.local` for overrides; never commit it. Only `VITE_`-prefixed variables reach the browser, so **never put a secret in one**.
- All commands run from `frontend/` (see `CLAUDE.md` §4). `npm install` (not `npm ci --ignore-scripts`) is required once so Husky installs the pre-commit hook.
- Pre-commit runs `eslint --fix` + `prettier --write` on staged files. If it fails, fix the cause; do not bypass with `--no-verify`.
- `npm audit` currently reports 7 moderate findings (not yet triaged). Do not run `npm audit fix --force`; triage and record the outcome in `PROJECT_STATUS.md`.

## 7. Known gaps

- Backend CORS must allow the dev origin before the first real API call works from the browser (Q-003).
- UI primitive library is OPEN (D-015): Tailwind 4 is chosen, and the ignore patterns suggest a vendored-primitives approach in `components/ui`, but no primitives or generator config exist yet. Do not add a large UI framework without a decision.
